# Журнал изменений

Типы для `FalloutNV.exe` 1.4.0.525 (GOG, SHA-256 `42fee7d6…b49c`): классы и перечисления из утёкшего Xbox 360 PDB,
проверенные по коду PC, поверх публичных имён из PDB xNVSE. Номер версии: `x.y` — новый раздел типов,
`x.y.z` — исправления без нового раздела. Подробности каждой версии — в `README_RU.md` её коммита («vX.Y: …»).

## [0.5.13] — 2026-10-25 — Привязка доказательства слота к имени функции (по аудиту Астры v0.5.12)

Аудит v0.5.12: архитектура принята; статус Confirmed у функций — условно (P1–P3). Оба PDB и заголовки — как в v0.5.12.

### Исправлено
- P1: прототип, разобранный вручную для слота vtable, переносился на функцию по адресу, даже если у адреса другое
  исходное имя или общее тело нескольких методов (ICF). Теперь доказательство записано у слота (`semantic_bindings`),
  а на функцию переносится только при `name_binding_status = matched`. Функций `Confirmed` — 1 (было 10), прототипов в
  IDA — 1.
- P3: `this_verified` переименован в `this_supported` (одобренное назначение, не доказательство типа), добавлен
  `this_basis` (`vtable-slot` / `method-heuristic`). Схема метаданных 3.

### Добавлено
- P2: охват реестра — «2204 изученные функции; остальные — Unclassified» (85 249 функций и 50 718 данных) в
  `verification.json`, README и плане скриптов.
- README: заметные предупреждения — обычный импорт PDB статусы не видит; скрипт проверяет указанный файл PDB, а не
  факт импорта; изменение совместимости C++ SDK с v0.5.12.
- Тесты: test_verification 23, Ghidra 43, IDA 15.

## [0.5.12] — 2026-10-25 — Исходные имена, статус доказанности — в метаданных (идея Андрея, ТЗ Астры)

Идея разделения оригинальных имён и статусов `Confirmed` / `VerifiedPrefix` предложена Андреем. Степень доказанности
больше не кодируется суффиксом в имени: она в метаданных, а недоказанные `sizeof` и ABI остаются неподтверждёнными.

### Изменено
- Строгий PDB и заголовок: `BGSSaveLoadFormHeader` и вложенный `FontManager::TextData` под исходными именами вместо
  `…_VerifiedPrefix` (одно определение, только подтверждённые поля, размер объекта игры 9…0xC и 0x40…0x44 не доказан).
  Буферы сохранения — прежняя раскладка. Research PDB побайтно тот же.
- В заголовке `FNV_VERIFIED_PREFIX_GUARD`: компилятор не даёт `new`, массивы, копирование и передачу по значению для
  этих двух классов (в PDB удалённых членов нет).

### Добавлено
- `verification_status` у всех 86 классов (`summary.json`: 84 Confirmed, 2 VerifiedPrefix) и реестр функций
  `evidence/verification.json`: 2204 функции (10 Confirmed, 2194 VerifiedPrefix) с фасетами подтверждения;
  `verification_coverage.csv`, `coverage_gaps.csv` (135 967 публичных символов xNVSE без статуса).
- `tools/verification.py` (статусы из уже собранных фактов), `tools/test_verification.py`, `tools/test_cpp_guard.py`.
- Скрипты Ghidra/IDA сверяют реестр с exe, summary.json и загруженным PDB (fail closed), ставят this/прототипы только
  по фасетам реестра, статус — в комментариях. Тесты на имитации: Ghidra 40, IDA 14.

## [0.5.9] — 2026-10-25 — Точный шаблон заглушки исключений (по аудиту Астры v0.5.8)

### Исправлено
- Заглушка обработчика C++ EH проверялась по названиям команд: `mov esp, 0`, `mov dword ptr [ecx], 0` перед
  `mov eax, FuncInfo` проходили (контрпримеры Астры). Теперь — точный шаблон MSVC /GS: только edx/eax/ecx, без записи
  в память, esp/ebp не меняются, 1–2 проверки cookie через проверенную `__security_check_cookie`. Все 4339 заглушек
  FalloutNV.exe ему соответствуют.
- Заглушка, действия раскрутки и сверяемые тела читаются по одной команде с проверкой границ каждой (раньше
  проверялось только начало диапазона).

### Добавлено
- 9 проверок в `tools/test_chaincheck.py` (48 всего): контрпримеры Астры, `push`/`mov ebp`, заглушка без cookie,
  две проверки cookie, секция, обрывающаяся посреди заглушки, действие раскрутки вне исполняемой секции.

PDB, заголовки и скрипты побайтно те же, что в v0.5.5–v0.5.8.
