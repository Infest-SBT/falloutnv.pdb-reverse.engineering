# Ограничения B01–B08

- **Стенд — эмулятор, не процессор.** Unicorn 2.1 (QEMU). Для этих тел (целочисленные `and/or/setne/sbb`) расхождение
  с настоящим CPU не ожидается, но это не проверено на железе.
- **Внешний вызов смоделирован.** `TESForm[18]` (`[vptr+0x48]`, Xbox — AddChange(int)) — заглушка с очисткой 4, по
  модели теста. Что делает настоящий AddChange, не проверялось; проверено только, что сеттер вызывает его у
  `this` с аргументом 1, как и сеттеры, опознанные по имени.
- **Тождество по поведению — новое правило.** Оно опирается на Xbox PDB как на источник списка виртуальных методов и
  их номеров (R3, R6). Без принятия правила Астрой слоты в строгий PDB не переносятся (этот выпуск PDB не меняет).
- **Смысл бита не доказан.** Доказано, что слот читает/пишет бит 0x40 (0x200) поля iFormFlags и что пара Get/Set
  согласована. Что бит 0x40 значит «с NPC говорили», по коду не выводится; совпадение имён Get/Set с одной основой —
  довод из Xbox, а не из PC.
- **ICF-слоты (40, 42) не решаемы этим методом.** Тело одно у двух виртуальных методов; различить их можно только по
  вызывающим с известным номером слота (не найдено) или по другому источнику.
- **Что не анализировалось:** вызывающие этих слотов; другие наследники TESForm, переопределяющие слоты 38/47/52
  (у семейства TESForm по RTTI одна реализация каждого из этих слотов — см. `evidence.json`).
